# agent-instruction-review

`AGENTS.md` や `CLAUDE.md` をレビューし、Baseline・Constitution・Articles の3層に整理する書き換え案を出す Agent Skill です。
コーディングエージェント向けの指示ファイルを運用している人に向けています。
指示ファイルは、規則を足すたびに長くなり、古い値や重複が残ります。このスキルを入れると、エージェントは指示を1つずつ検査し、少数の上位原則の候補と、直し方の案を報告します。

## できること

- 指示の検査: 機密情報、古くなる値、指示ファイルに置く内容ではない文章、重複、1つの意味に読めない表現を見つける
- 参照先の確認: コマンドの入口と参照先のファイルが、リポジトリにあるかを確かめる
- 上位原則の候補の提示: 既存の指示を「条件・行動・目的」に書き直し、すべてのエージェントが同じ行動を選んでも成り立つかを確かめて、Constitution の候補を導く
- 書き換え案の提示: 直せる指摘に `Before` と `After` を付ける
- 報告の形式の検査: 同梱のスクリプトで、報告に必須の項目がそろっているかを確かめる

指示ファイルは3層に整理します。

| 層 | 書く内容 |
| :-- | :-- |
| Baseline | 作業を始めるための入口。コマンドと、参照先のファイル |
| Constitution | 長く維持する上位原則 |
| Articles | Constitution を具体的な状況へ当てはめた規則 |

Constitution の候補を採るかどうかは、人間が決めます。エージェントは候補を示すところで止まり、返事を待ちます。

次のことは対象外です。

- 指示ファイルの編集。成果物はレビュー報告で、書き換えは別に頼んだときだけ行う
- アーキテクチャの説明や型の一覧が、コードと合っているかの照合。これらは別の文書へ移す指摘になる
- コマンドの実行。コマンドが今も通るかは「未確認」と報告する

## 動作環境

`SKILL.md` を読み込むエージェントで使います。作者は Claude Code で使っています。

- 報告の形式の検査には [uv](https://docs.astral.sh/uv/) が要る。uv が Python 3.11 以上を用意する
- 規則と報告は日本語で書かれている

## インストール

[skills](https://github.com/vercel-labs/skills) の CLI で入れます。

```bash
npx skills add sumx21t-3310/agent-instruction-review
```

入れる前に中身を確かめるときは、`--list` を付けます。一覧を表示するだけで、インストールはしません。

```bash
npx skills add sumx21t-3310/agent-instruction-review --list
```

CLI を使わずに、エージェントのスキル用フォルダへ clone しても使えます。Claude Code の場合:

```bash
git clone https://github.com/sumx21t-3310/agent-instruction-review.git $HOME/.claude/skills/agent-instruction-review
```

## 使い方

レビューしたいリポジトリで、指示ファイルのレビューを頼みます。

```text
AGENTS.md をレビューして
```

エージェントは、次の順に進めます。

1. 指示を検査し、参照先があるかを確かめる
2. 指示から上位原則の候補を導く
3. 候補を採るかどうかをたずねる
4. 採用された原則に沿って、残りの規則を整理する
5. 報告をファイルに書き出し、形式を検査する

候補の採否に返事がないときは、手順3までの報告を出して止まります。

報告の形式は、スキルのフォルダで次のコマンドを実行して確かめられます。`OK` と表示されれば合格です。

```bash
uv run assets/check-review.py <報告のファイル>
```

## ファイル構成

| ファイル | 内容 |
| :-- | :-- |
| `SKILL.md` | スキルの本体。手順、停止条件、判定、報告の形式 |
| `references/checks.md` | 検査ごとの基準と、Good と Bad の例 |
| `assets/check-review.py` | 報告の形式を検査するスクリプト |

## 開発段階

バージョン番号とリリースはまだありません。

- 試した対象は、実際のリポジトリの `AGENTS.md` が1つと、問題のある規則を入れたテスト用のファイルが1つ
- 指示から抽出する格率の数と、候補の数は、実行ごとに変わる
- 階層になった `AGENTS.md` の継承と競合の検査は、テスト用のファイルでしか試していない
